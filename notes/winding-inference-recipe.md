# Winding-inference recipe for a new 9.362 um scroll (PHerc0191)

Goal: produce the `winding_inference/` compact crossing store that the Spiral
fitter consumes when `dense_spacing_mode: "winding_model"`, for a scroll whose
level-0 volume is 18977 x 8387 x 8387 voxels at 9.362 um, with a local OME-Zarr
pyramid (levels 0-5), Lasagna normals, and `umbilicus.json`.

Everything below is taken from the local checkout and the public Hugging Face
repo. Where the docs/code say nothing, the text says "not stated". Flags and
commands are quoted verbatim from the sources listed at the end.

---

## 0. Pipeline shape (what the docs actually describe)

```
bootstrap Spiral fit (.ckpt, no winding model)      <- prerequisite, see 7.1
        |
        v
infer_winding_volume.py  FIT.ckpt  CACHE.zarr  --native-phase-only ...   (GPU)
        |   lossless native phase cache (zarr v3 group, attr complete=true)
        v
export_spiral_supervision.py  CACHE.zarr  STORE_DIR  --workers N          (CPU)
        |   STORE_DIR/manifest.json + shard_*/ *.npy  (artifact_type
        |   "winding_inference_crossings", format_version 1)
        v
<dataset>/winding_inference  (or paths.winding_inference in spiral-scroll.json)
        |
        v
fit_spiral.py with dense_spacing_mode = "winding_model" (+ outer_shell)
```

The optional third `infer_winding_volume.py --phase-cache ...` reconstruction
(full-resolution `winding` / `confidence` / `crossing_prob` rasters) is NOT
needed by the fitter; it is documented in `NATIVE_PHASE_CACHE.md` for
visualization/other consumers and summarized briefly in 2.4.

## 1. Inputs the winding model takes, and what it outputs

### 1.1 Model input (per slab)

- A single ray-aligned CT slab `[H, W, L]` = `transverse_size x transverse_size
  x ray_length` = `128 x 128 x 384` samples, sampled with `spacing: 1.0` voxel
  steps of the selected pyramid level (`winding_model.py` docstring;
  `volume_slab_extractor.py`: "sampled at `spacing` voxel steps on every axis
  so the ray axis stays at full volume resolution"; HF `config.json`:
  `"ray_length": 384, "transverse_size": 128, "spacing": 1.0, "sampling":
  "trilinear"`).
- The ray is seeded on a fitted sheet and "cast along the outward surface
  normal with the seed crossing at the ray midpoint" (`infer_winding_volume.py`
  docstring). Seeds come from the Spiral fit, not from the CT.
- Voxel size / level: the checkpoint was trained on PHerc0139 and PHerc1667
  `2.399um` volumes at `"volume_scale": 2` (i.e. 2.399 x 4 = 9.596 um/voxel)
  plus PHercParis4 `s1_2um_ds2.zarr` at `"volume_scale": 0` (voxel size of that
  volume: not stated in-repo). The HF repo is named `winding_model_9um`. For a
  9.362 um scroll use `--volume-scale 0` of the local mirror (the PHercParis4
  examples also use `--volume-scale 0`).
- Reference zarr layout: `--reference-zarr` is "volume zarr (multiscale group or
  array); scale-0 shape defines the output coordinate space and the selected
  scale is sampled for inference". `VolumeSlabExtractor.scaled_volume_path`
  selects `<reference>/<scale>` only if `<reference>/<scale>/.zarray` exists
  (zarr v2 marker); otherwise it falls back to the group path itself. Whether
  a zarr-v3 (`zarr.json`) pyramid is accepted: not stated. Volume reads go
  through the `vc` (volume-cartographer) bindings, not through `zarr`.
- Umbilicus: `--umbilicus umbilicus.json` ("default: search near checkpoint /
  SPIRAL_DATASET"). Used for seed-ray orientation in `--seed-source spiral`
  mode and recorded in the cache attrs in both modes; the network itself does
  not see it.
- Normals: the Lasagna normals are NOT an input to the winding model (the ray
  direction is the surface normal of the fitted mesh/spiral, computed by the
  script). Not stated anywhere that lasagna `normal_x/normal_y` are read.
- Seed grid: generated by the script from the fit checkpoint:
  `--winding-range FIRST LAST`, `--winding-step`, `--seed-spacing` (voxels along
  the winding and along z), `--z-range Z_MIN Z_MAX`; `--seed-source meshes`
  (default; seeds on the checkpoint's exported `w###_spliced_*` tifxyz meshes
  under `<checkpoint dir>/meshes/<newest>/` or `--meshes-dir`) or
  `--seed-source spiral` (raw fitted spiral surface). A previously computed seed
  file can be reused with `--seed-rays-npz` (written as
  `OUTPUT.tmp/seed_rays.npz`).

### 1.2 Model output

Per column (one ray-parallel line of voxels per output column) "a monotone
relative winding phase: softplus increments accumulated along the ray axis";
crossings are "the integer passages of the monotone phase itself" because the
HF checkpoint is headless (`"use_crossing_head": false`, `"use_variance_head":
false`, `"full_resolution_head": true`, `"decoder_levels": 1`).

Native phase tensor per slab: `native_columns x native_columns x ray_length`
float32 where `native_columns = transverse_size // column_stride` read from the
checkpoint's embedded `config` (`infer_winding_volume.py`
`_initialize_native_phase_cache`). `NATIVE_PHASE_CACHE.md` says "The stored
phase is always the model's native `32 x 32 x 384` float32 output" — that is a
`column_stride: 4` model. The HF `config.json` (= local
`train_config_ft7.json`) has top-level `"column_stride": 1` and the model's
`column_stride` property returns 1 for `full_resolution_head`, so with the HF
checkpoint the cache stores `128 x 128 x 384` float32 per slab (25.2 MB
uncompressed vs 1.57 MB). See 4.4 and 7.6 — this is the single biggest
planning risk.

Artifacts:

1. Native phase cache (`--native-phase-only`): zarr group with
   `phase/shard_*`, `valid/shard_*` (bit-packed `128 x 128 x 384` masks),
   `frame/shard_*`, `available/shard_*`, `rays/{seed_xyz,direction_xyz,
   seed_winding}`, root attrs incl. `artifact_type:
   "winding_native_phase_cache"`, `complete`, `z_range`, `seed_windings`,
   `dr_per_winding`, `umbilicus`, `model_ckpt`, `reference_zarr`,
   `volume_scale`, `column_stride`, `native_columns`, `elapsed_seconds`.
2. Compact Spiral supervision (`export_spiral_supervision.py`): directory with
   `manifest.json` (`artifact_type: "winding_inference_crossings"`,
   `format_version: 1`, `coordinate_order: "zyx"`, `coordinate_space:
   "reference zarr scale-0 voxels"`, `fingerprint`, `num_rays`,
   `num_crossings`, `shards[]`) and per-shard `.npy` arrays
   `ray_origin_zyx`, `ray_step_zyx`, `crossing_t`, `crossing_level` (int16,
   relative to the seed anchor), `crossing_offsets`, `seed_winding`. Only the
   centre ray of each slab is exported; "uses only the contiguous valid
   interval containing the seed anchor, and drops the first and last two
   crossings" (`--edge-trim 2`, `--edge-margin 8`).
3. (Optional) full-resolution reconstruction: `winding` int16 / `confidence`
   uint8 rasters (downsampled by `--output-downsample`), `points/*`,
   `strips/*`, `crossing_prob` with `--prob-volume`.

Flags that are valid in `--native-phase-only` mode (the doc: "Cache creation
uses only"):

- seed selection: `--z-range`, `--winding-range`, `--winding-step`,
  `--seed-spacing`, `--seed-source`, `--seed-rays-npz` (plus `--meshes-dir`,
  `--umbilicus`);
- model and volume extraction: `--model-ckpt`, `--reference-zarr`,
  `--volume-scale`, `--batch-size`, `--extract-threads`,
  `--volume-cache-bytes`;
- execution: `--gpus`, `--compile`, optional `--max-slabs`
  (`--max-slabs-selection random|first`).

Everything else is rejected: `parse_args()` errors with "--native-phase-only
does not materialize derived outputs; remove these reconstruction-only
options" for `--column-step`, `--column-upsample`, `--threshold`,
`--min-distance`, `--min-prob-keep`, `--max-level`, `--prob-volume`,
`--archive-workers`, `--prob-volume-floor`, `--prob-combine`,
`--prob-ray-margin`, `--prob-column-margin`, `--merge-workers`,
`--prob-column-step`, all `--prob-phase-*`, `--output-downsample`,
`--slab-center-width`, `--phase-cache-winding-stride`,
`--phase-cache-allow-relocated-inputs`, `--phase-registration`, all
`--phase-sync-*`, `--decode-workers`.

Defaults (argparse): `--volume-scale 0`, `--seed-source meshes`,
`--winding-step 8`, `--seed-spacing 96.0`, `--batch-size 8`,
`--extract-threads 8`, `--volume-cache-bytes` = checkpoint's
`volume_cache_bytes` (HF config: `356515840` bytes per GPU worker), `--gpus`
= all visible CUDA devices, `--z-range` = checkpoint's fitted z range,
`--winding-range` = checkpoint's `output_first_winding`..
`shell_outer_winding_idx`.

Workers: one plain worker process per GPU ("no DDP/torch.distributed");
`--extract-threads` slab-extraction threads per GPU worker. There is no
separate CPU-worker flag for cache creation. Progress: tqdm bar
"inference" in slabs; the run ends with `[main] wrote native phase for
A/T slabs to OUTPUT in Ns` and sets root attr `complete: true`. "Do not
reconstruct from a cache whose root `complete` attribute is false."

Scratch: `OUTPUT.tmp` (`Path(args.output).with_suffix(".tmp")`, so for
`winding_native_phase.zarr` the scratch dir is `winding_native_phase.tmp`),
holding `seed_rays.npz` and per-GPU `shard_<gpu>.npz`.

Smoke test first (recommended, see 4.4): add `--max-slabs 256
--max-slabs-selection first` to measure bytes/slab and slabs/s.

final directory appears atomically. Afterwards:


### 2.3 Wire the store into the dataset

`fit_spiral.py` resolves the input through the declarative catalog:
`FitInputSpec("winding_inference", "directory",
conventional_relative="winding_inference", ...)`. So either

- place/symlink the export directory at `<dataset>/winding_inference`, or
- set `paths.winding_inference` in `<dataset>/spiral-scroll.json`:

```json
{
  "schema_version": 1,
  "name": "PHerc0191",
  "voxel_size_um": 9.362,
  "spiral_outward_sense": "CW",
  "normal_zarr_group": "<group>",
  "lasagna_scale": <factor>,
  "paths": {
    "winding_inference": "/path/to/winding_inferences/PHerc0191/winding_spiral_supervision"
  }
}
```

(`spiral_outward_sense`, `normal_zarr_group`, `lasagna_scale` values are
scroll-specific and must be read off this scroll's data; see the fitter README
"Scroll specification".) Then select the mode for a headless fit:

```bash
FIT_SPIRAL_CONFIG_OVERRIDES='{"dense_spacing_mode":"winding_model","z_begin":Z0,"z_end":Z1}' \
  python fit_spiral.py --dataset /path/to/dataset
```

(`fit_spiral.py` CLI: `--dataset` (required), `--scroll-spec`, `--cache`;
`FIT_SPIRAL_CONFIG_OVERRIDES` must contain only `Config` keys. Output-directory
handling for the headless CLI: not stated in the lines read.)

```bash
  --column-step 4 \
  --max-level 9 \
  --prob-volume \
  --prob-column-step 1 \
  --prob-combine phase \
  --prob-phase-max-level 9.5 \

  --archive-workers 4 \
```

`column_stride` (for the HF stride-1 model use `--column-upsample 1`);
`--phase-registration overlap` + `--prob-combine phase-label` is the
topology-free alternative to anchoring every seed to an integer crossing.

## 3. Choosing `--winding-range`, `--winding-step`, `--z-range`

### 3.1 What the PHercParis4 example used and why

- `--z-range 7500 9500` (2,000 slices), `--winding-range 10 130`,
  `--winding-step 3` (seed sheets 10, 13, ..., 130 = 41 sheets),
  `--seed-spacing 60` voxels -> "139,205-slab PHercParis4 workload"
  (`NATIVE_PHASE_CACHE.md`). That is ~33 z-rows x ~4,176 seeds/row, i.e.
  ~100 seeds per sheet per row.
- `10` is the fitter's `output_first_winding` default; `130` is the fitter's
  `shell_outer_winding_idx` default (`config.py`: `shell_outer_winding_idx =
  130`, `shell_outer_winding_margin = 10`; `gap_expander_num_windings` "Must be
  at least shell_outer_winding_idx + 3"). These are also the script's
  `--winding-range` defaults when the flag is omitted.
- Why step 3 rather than the default 8: the docs do not say explicitly. The
  argparse help for `--max-level` gives the overlap rule for reconstruction:
  "keep <= 2x winding-step so slabs still overlap"; the fast-path doc calls
  3-winding anchor spacing a cache that "deliberately overlap[s] adjacent
  128-voxel slabs heavily". For the Spiral export the step controls how many
  independent centre rays cross each sheet.
- The ray spans 384 samples (+-192 voxels around the seed). With the fitter's
  default `initial_dr_per_winding` = 16 voxels (`cfg.get("initial_dr_per_winding",
  16.0)` in the seeding code) a ray covers roughly +-12 windings, so step 3
  gives ~8x sheet coverage and step 8 ~3x. (Derived, not stated.)

### 3.2 For PHerc0191 (~60-130 windings, z 0-18977)

- `--winding-range`: `10 <outermost winding index of the bootstrap fit>`.
  Windings are inclusive (`range(first, last + 1, step)`). In `meshes` mode
  every selected winding needs an adjacent `w(w+-1)_spliced*` mesh for normal
  orientation ("winding {w} has no adjacent mesh to orient against"), so the
  bootstrap fit must have exported meshes one past each endpoint. The
  bootstrap fit's `shell_outer_winding_idx` should be set to this scroll's
  actual outer winding and `gap_expander_num_windings >=
  shell_outer_winding_idx + 3`.
- `--winding-step`: 3 reproduces the documented cache; 8 (default) cuts slab
  count ~2.6x. The fitter's relative-pair sampler needs rays with
  `length >= min_delta + 1` crossings (`winding_model_relative_pair_delta =
  [3, 15]`), which the 384-sample ray provides regardless of step.
- `--z-range`: the script clamps it to the fit checkpoint's `[z_begin,
  z_end)` ("empty z range ... after clamping to the checkpoint's"), so the
  bootstrap fit must cover the slices you want supervised. The fitter later
  filters rays to its own `[z_begin, z_end)` at load ("rays whose crossings
  cannot intersect the configured z-range are excluded"), so one store
  covering the whole fitted range serves any sub-window fit. For the full
  0-18977 range that is ~9.5x the PHercParis4 z extent: at the same
  `--winding-step 3 --seed-spacing 60` expect on the order of 1.3 M slabs;
  at defaults (`--winding-step 8 --seed-spacing 96`) roughly 0.2 M. Also the
  per-step sample counts in the fitter are scaled to the z range relative to
  its 9,500-slice reference (`scale_counts_for_z_range`).
- `--seed-spacing`: 60 (doc) vs 96 (default); the fast-path doc also mentions
  a 48-voxel cache. Smaller spacing = more rays per sheet = more supervision
  and proportionally more slabs/disk.
- Multiple caches/stores: the exporter takes one `source`, the fitter one
  `winding_inference` directory; merging stores is not provided (not stated).

## 4. Hardware / runtime statements

### 4.1 GPU memory

- `infer_winding_volume.py` line 90 (comment): "H100-class devices have ample
  memory after this model's forward (~10 GiB)." Forward runs under
  `torch.autocast("cuda", dtype=torch.bfloat16)` with default `--batch-size 8`
  on `128 x 128 x 384` slabs (6 axial-attention blocks, `trunk_dim 192`).
- Reconstruction accumulators: `_PROB_GPU_FLUSH_RECORDS = 1 << 26` records
  are held on the GPU before flushing (constant, not a CLI flag; 67 M records
  x 28-32 B ~ 2 GiB).
- No statement says "12 GB is insufficient". The only quantified figure is the
  ~10 GiB forward on H100-class hardware, which with CUDA context and
  extraction buffers leaves essentially no headroom on a 12 GB card; the
  obvious mitigations are `--batch-size 1` or `2` and omitting `--compile`.
  Whether that fits: not stated / untested.
- Fitter side: the whole store is "copied to each fitting GPU at startup"
  (float32 origins/steps, float32 `crossing_t`, int32 levels) — hundreds of
  MB at most for ~1 M rays.

### 4.2 Time

- Cache creation time for the 139,205-slab PHercParis4 run: not stated (the
  cache root attr `elapsed_seconds` records it; the console prints
  `slabs/s`). `--compile` "adds ~a minute of warmup per GPU; pays off on long
  runs".
- Fast full-resolution reconstruction: "measured 1-2 hour configuration" on 7
  GPUs (`--gpus 0,1,2,3,4,5,6`) for the 48-voxel / 3-winding PHercParis4 cache.
  Full (all-slab, full-footprint) reconstruction: not stated.
- Exporter time: not stated (manifest records `elapsed_seconds`).

### 4.3 CPU workers

- Cache creation: `--extract-threads 8` per GPU worker; `--volume-cache-bytes`
  per GPU worker (default from checkpoint, 356,515,840 B).
- Export: `--workers` default `min(32, cpu_count)`; tasks are 256-ray chunks
  aligned to 32-ray physical shards; "worker count is not limited by the
  number of GPU/source shards".
- Reconstruction: `--archive-workers` (default `min(8, cpus)`),
  `--merge-workers` (default `min(32, cpus)`), `--decode-workers 3` per GPU
  worker, `--phase-sync-workers` (default `min(16, cpus)`).

### 4.4 Disk

- Stated: "For the 139,205-slab PHercParis4 workload, the phase payload is
  approximately 219 GB uncompressed and 144-150 GB losslessly compressed.
  Validity and frame metadata are small by comparison." 219e9 / 139,205 =
  1.573 MB/slab = exactly `32 x 32 x 384 x 4` bytes, i.e. a `column_stride 4`
  model.
- With the HF checkpoint (`column_stride: 1`, `full_resolution_head: true`)
  the cache writer allocates `128 x 128 x 384` float32 per slab = 25.2 MB
  uncompressed (16x). Compression ratio for that case: not stated. Scaling
  the doc numbers: 139 k slabs -> ~3.5 TB uncompressed; a whole-scroll 1.3 M
  slab run -> ~33 TB uncompressed. Measure on a `--max-slabs` smoke run
  before committing (`du -sh CACHE.zarr`, and check root attr
  `native_columns`).
- Exporter output: "uncompressed, GPU-resident-friendly" `.npy` arrays, only
  centre rays, so it is small relative to the cache (not quantified).
- Scratch `OUTPUT.tmp` lives next to the output.

### 5.2 Environment

## 6. Fitter side: what `dense_spacing_mode: "winding_model"` requires

- `dense_spacing_mode` enum: `["grad_mag", "winding_model"]`; the `Config`
  default is already `"winding_model"` (`config.py`: `self.dense_spacing_mode
  = "winding_model"`). It is a `_PREPARED_INPUT_FIELDS` key (full rebuild).
- Gate (`fit_session.py`):
  `_winding_model_enabled = dense_spacing_mode == "winding_model" and
  input_use_winding_inference and input_use_outer_shell`. Both switches
  default `True`. README: "Disabling a prerequisite also disables its
  dependent supervision: winding inference needs the outer shell."
- Outer shell: `FitInputSpec("outer_shell", "directory",
  conventional_relative="outer_shell", required=_outer_shell_required)`; a
  tifxyz directory loaded with `load_tifxyz(self.shell_path)`; error if
  missing: "the outer shell is required by shell losses or winding-model
  supervision, but no outer shell path is set". It builds a `ShellPolarMap`
  (`shell_num_theta_bins 720`, `shell_table_smooth_sigma_z 4.0`,
  `shell_table_smooth_sigma_theta 1.0`, `shell_min_confidence 0.25`,
  `shell_huber_delta 16.0`, `loss_weight_shell_outer 1.0`,
  `shell_outer_winding_idx 130`, `shell_outer_winding_margin 10`). In the
  winding loss a pair is valid only if `shell_valid & (sample_radius <=
  shell_radius)` for both points — crossings outside the shell are ignored.
- Store path: `paths.winding_inference` or `<dataset>/winding_inference`;
  `fit_spiral.py` raises "dense_spacing_mode='winding_model' requires the
  compact winding-inference store" if the directory is missing.
- Loss terms and weights (`config.py` defaults):
  `loss_weight_dense_spacing = 12.0` -> `dense_spacing_winding_model_relative`
  (long pairs, separation drawn from `winding_model_relative_pair_delta =
  [3, 15]`), `loss_weight_dense_spacing_density = 12.0` ->
  `dense_spacing_winding_model_density` (adjacent passages),
  `winding_model_huber_delta = 0.5`, `sample_count_winding_model_relative_pairs
  = 128000`, `sample_count_winding_model_density_pairs = 128000` (both
  `scale_with_z`; the README's "default 24,000 samples per step are split
  evenly" is out of sync with `config.py`). `loss_weight_min_spacing = 2.0`
  and the Lasagna normals loss remain active alongside. Residual =
  `(unwrapped_r[1] - unwrapped_r[0]) / dr_per_winding - target`, Huber, mean
  over valid pairs; metrics
  `dense_spacing_winding_model_{relative,density}_{valid_fraction,
  residual_abs_mean,residual_abs_p50,residual_abs_p95}`.
  `loss_weight_dense_spacing_density > 0` in `grad_mag` mode prints a
  WARNING and is inactive.
- Validation of the store (`winding_supervision.py` `WindingInferenceStore`):
  `manifest.json` present; `artifact_type == "winding_inference_crossings"`;
  `format_version == 1`; `coordinate_order == "zyx"`; manifest `fingerprint`
  equals the sha256 of the canonical manifest minus `fingerprint`,
  `elapsed_seconds`, `export_workers`, `rays_per_task`, per-shard
  `elapsed_seconds`; every array's sha256/shape/dtype (sha256 check
  disabled with `FIT_SPIRAL_VERIFY_WINDING_INFERENCE=0`); per-shard
  `seed_winding` length == ray count; offsets/crossing arrays consistent.
  Then rays are filtered to `[z_begin, z_end)`; the load prints `loaded
  winding inference: N rays (M intersect z-range ...), K crossings`. The
  fingerprint is stored in checkpoints as `winding_inference_fingerprint`.
  `fit_session.py` request validation also checks `manifest.json`,
  `artifact_type`, `format_version`. Coordinates are used as-is (no
  rescaling): the store's `coordinate_space` is "reference zarr scale-0
  voxels", so the fit must work in the same frame as `--reference-zarr`
  level 0.

## 7. Gotchas, failure modes, winding-numbering reconciliation

7.1 Bootstrap dependency (chicken-and-egg). `infer_winding_volume.py`'s first
positional is "fitted Spiral checkpoint (.ckpt)" and the default seed source
needs that fit's exported `meshes/<run>/w###_spliced_*` directories (with
`meta.json` `scale`). For a new scroll you must first fit PHerc0191 without
the winding model — e.g. `FIT_SPIRAL_CONFIG_OVERRIDES='{"dense_spacing_mode":
"grad_mag"}'` (uses the packed Lasagna `gradient_magnitude` store) or
`{"input_use_winding_inference": false}` — export meshes, then infer, export,
and refit with `winding_model`. The cache records `fit_checkpoint` and
`umbilicus` in its attrs.

7.2 Winding numbering. The compact store's `crossing_level` is RELATIVE to
each ray's seed passage (`registered = phase - phase[anchor]`; level 0 at the
ray midpoint), and the fitter uses only `levels[:, 1] - levels[:, 0]` as the
target; `seed_winding` is loaded only for a length check. Hence the model's
absolute winding numbering, the bootstrap fit's `output_first_winding`, and
the final fit's numbering need not agree, and no umbilicus-based re-indexing
is needed for the loss. What must agree is direction: rays are oriented
"toward the next-higher winding" (`meshes` mode: sign against the adjacent
mesh; `spiral` mode: "away from the umbilicus in the yx plane"), the exporter
stores crossings in ascending `t` with increasing level, and the fitter
requires `target > 0` and predicts `(unwrapped[1] - unwrapped[0]) /
dr_per_winding` outward. If the bootstrap fit's `spiral_outward_sense` or the
seed normals were flipped, residuals would sit near `2 x target`; watch
`..._residual_abs_p50`. Absolute numbering only matters for the optional
`winding` raster, which anchors each slab to its `seed_winding`
(`--phase-registration anchor`) or uses it as a weak prior (`overlap`).

7.3 Seed quality. `--seed-source spiral` "can sit a winding or more off the
true sheet and then mislabels the anchor" (affects the absolute raster, and
makes the centre-ray anchor sit off-sheet; the exporter still trusts the
contiguous valid run around the midpoint). Prefer `meshes` once verified
patches exist; with none, spliced meshes equal the raw spiral (not stated).

7.4 z coverage. `--z-range` is clamped to the checkpoint's fitted range; an
empty intersection raises. Fit the bootstrap over the z you need.

7.5 Headless only. `--native-phase-only`/`--phase-cache` raise "native phase
caching currently requires a headless phase model" for crossing-head models.
The HF checkpoint is headless.

7.6 Cache size with the HF model. See 4.4: `native_columns = transverse_size
// column_stride` = 128 for `column_stride 1`, so budget ~25 MB/slab
uncompressed, not the documented 1.57 MB. Reduce slab count via
`--seed-spacing`, `--winding-step`, narrower `--z-range`, or run z windows
sequentially (one store per fit window). No centre-ray-only cache option
exists in the CLI (the exporter discards all but the centre ray).

7.7 Paths and reruns. Output must differ from `--phase-cache`; the exporter
refuses an existing `output`; reconstruction validates `model_ckpt` and
`reference_zarr` against cache attrs (`--phase-cache-allow-relocated-inputs`
to relocate). `OUTPUT.tmp` is derived with `with_suffix(".tmp")`. Stale
`prob_spill_*`/`winding_spill_*` dirs are removed on rerun. `--seed-rays-npz`
reuses `OUTPUT.tmp/seed_rays.npz`.

7.8 Reference zarr format. `scaled_volume_path` tests for `<ref>/<scale>/
.zarray` (zarr v2). If the local PHerc0191 mirror is zarr v3, `--volume-scale
0` resolution falls back to the group path — behaviour then: not stated;
verify on the smoke run.

7.9 Fitter gating surprises. Because `dense_spacing_mode` defaults to
`winding_model` and both `input_use_*` default `True`, a fresh dataset without
`winding_inference/` and `outer_shell/` fails input validation until you
either provide them or disable the source. A too-tight outer shell silently
drops supervision near the outside (`shell_pair_valid`). `z_begin/z_end` scale
the pair sample counts.

7.10 Docs drift. `NATIVE_PHASE_CACHE.md` says the phase is "always 32 x 32 x
384" and quotes `large_9/ckpt_015000.pth` (unpublished); the README quotes
24,000 samples/step vs `config.py`'s 2 x 128,000. Trust the code paths cited
here.

7.11 Hardware. Only H100-class memory is characterised (~10 GiB forward at
batch 8). On a 12 GB card start with `--batch-size 1`, no `--compile`, and a
`--max-slabs` smoke run; multi-GPU is one process per GPU sharing the slab
list contiguously.
