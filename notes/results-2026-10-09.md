## Interpretation (11:30 UTC)
- The initial winding spacing fixes the spiral's radial extent (dr 16 → 21 mm at w129; dr 32 → 32 mm at w100); the optimizer does not re-learn it.
- Stretching the whole spiral outward (shell loss) lowers track satisfaction, so the inner windings are already at about the right spacing. The outer, fat sectors need *more* windings at *wider* spacing, while the thin sectors have the same sheets compressed to ~0.13 mm (ray audit under-counts them). A crushed scroll has the same winding count in every direction; the spacing varies ~2.5× by sector. The flow field must therefore be strongly anisotropic — `sym_dirichlet` (weight 10, loss term 36–45 at the end) resists exactly that.
- Winding-model smoke run: 51,360 slabs at (step 3, spacing 60) → 776 GB at the measured 15.1 MB/slab — too big; the full run uses (step 8, spacing 96): 7,102 slabs, ~107 GB, 1.29 s/slab on two GPUs (~2.5 h). Bootstrap = exp-30k.
- Queued: `exp-dirlow` (sym_dirichlet 2.5, dense shell at w125, gap 130) after WINDING-EXIT; `exp-wm` (dense_spacing_mode winding_model + same shell) after EXPORT-EXIT.
- Fiber inference attempt 1 failed: `ModuleNotFoundError: No module named 'lasagna'` (friction #8); attempt 2 running with `PYTHONPATH=villa` on GPU 0, 20,172 tiles at 0.7 s → ~15:15 UTC; tracer direction-field test follows.

## Fiber direction field → tracer (12:50–13:10 UTC)
- Fiber inference (SD2 checkpoint, level 0, crop z 8500–10500, `--inference-scaledown-power 2`) finished in ~1.6 h on one 3060: `data/PHerc0191/fiber/band8500-10500/{fiber_nx,fiber_ny,fiber_presence}.ome.zarr` (levels 2–4, uint8, 64³ chunks, ~0.8 GB each). The manifest `fiber.lasagna.json` describes nx/ny as Lasagna compact normals: the Fiber model's two fibre directions are crossed into a sheet NORMAL and encoded `(u8 − 128)/127` with nz implied.
- `vc_grow_seg_from_seed` `direction_fields[].zarr` expects one root with `x/<scale>`, `y/<scale>`, `z/<scale>` pyramids (same uint8 encoding; cf. the public `s5-fiber-directions.zarr/{horizontal,vertical}/{x,y,z}`), with `dir` ∈ {horizontal, vertical, normal} and optional `weight_zarr/<scale>`. First tracer attempt pointed it at `fiber_presence.ome.zarr/2` as "horizontal" and aborted (`zarr: cannot detect version at …/2/x/1`).
- Fix: `bin/make_dirfield_zarr.py` symlinks `x → fiber_nx`, `y → fiber_ny` and materialises `z/2 = sqrt(1 − nx² − ny²)` (same chunks/compressor) → `fiber/band8500-10500/dirfield.zarr`; `bin/tracer_dirfield_test2.sh` uses `{"zarr": dirfield.zarr, "dir": "normal", "scale": 2, "weight_zarr": fiber_presence.ome.zarr}` with honest exit codes (`tracer-dirfield2.log`, DIRTEST2-EXIT). The same converter can turn the community Lasagna normals (`lasagna/<id>/PHerc0191_{nx,ny}.ome.zarr`) into a second normal field.

## Tracer: the missing input was the normal grid (13:15 UTC)
- Tracer test 2 (Fiber normal field as `dir: normal`, presence weight): gen 70 → 6.87 cm², gen 150 → 21.2 cm², both still flat discs (QA: "extents 1532 × 1341 × 263 vx, NOT sheet-like"; the render is a cut across laminated sheets). The direction field only re-oriented the disc (normal now along x); every growth candidate was accepted.
- Root cause candidate: the docs (`35_segmentation.md`) mark **normal grids as REQUIRED** for the tracer, passed as `params.normal_grid_path` (+ `normal_grid_level`); the tracer's NORMAL (weight 10) and SNAP losses are only built when it is present (`GrowPatch.cpp` `TraceData.ngv`), and the CLI runs silently without it. None of our earlier traces set it. We have PHerc0191 normal grids (`data/PHerc0191/normal-grids`, xy plane only, 18,977 `.grid` files, spiral-step 20, level 0); the loader tolerates missing xz/yz planes (`query()` returns nullopt).
- Running: `grow-test/dirfield2/params_ng70.json` = direction field + `normal_grid_path` (xy) → `grow_ng70.log` (NGTRACE-EXIT), output `out_ng70/`.
- Side finding: a local volume path for `vc_grow_seg_from_seed -v` needs a volpkg-style `metadata.json` with `type`; our bare OME-Zarr mirror lacks it (remote URLs work).
